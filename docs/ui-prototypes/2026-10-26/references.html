ADIT / DESIGN RATIONALE / 2026.10.26

少一层重复，多一层秩序。

本组原型只比较导航与会话组织：侧栏不再复刻主区域的主机清单，多连接不再无限增加顶部标签。主机、终端输出、地址及远程桌面均为合成内容；没有真实网络连接。

借鉴哪些主流模式

官方参考确认的模式Adit 原型如何取舍
SecureCRTSession Manager 管理保存的资源，Active Sessions Manager 管理打开的连接；两者提供停靠和查找能力。B 保留会话树作为资源入口，主区域专注会话内容；侧栏可收起。
Termius工作区按任务组织连接；Focus 模式显示一个终端和侧边会话列表，Split 模式同时展示多个终端。A 借鉴 Focus 模式的垂直会话切换；C 借鉴任务工作区和 Focus / Split 切换，具体资源导航为 Adit 的设计探索。
VS Code固定标签和编辑器组用于组织大量打开内容，也可采用紧凑的标签显示方式。B 将可见标签上限设计为 3 个，隐藏的远程连接继续存在。3 个是本原型的取舍，不代表参考产品的默认值。
MobaXterm侧栏可作为会话管理器，主区域提供标签终端与多终端布局。B 取熟悉的连接树模型；C 取多目标同屏的任务模式。资源列表与内容区各自负责一件事。

三套方案，解决同一个问题

方案侧栏职责顶部与主区域取舍
A · 优先推荐
资源与工作分离		工作区：仅已打开连接。
资源库：仅分组，不再列出具体主机。		0 个逐会话标签。
主区域：单个活动会话，或唯一的资源列表。		消除重复最彻底，适合多连接长时间工作；需要在资源库和工作区之间切换。
B · 熟悉易迁移
连接树与有限标签		保存的主机树是唯一的资源管理入口。最多 3 个标签：固定/常用与当前会话。全部连接通过切换器访问。学习成本低；主机名称仍会出现在活动标签中，但右侧不再重画完整主机目录。
C · 并行排障
任务工作区与分屏		只显示任务工作区，不显示会话或主机清单。没有逐会话标签。任务内多个会话直接分屏，可聚焦单个窗格。适合多机对照；需要引入任务工作区的管理概念，产品改动范围更大。
建议先实现 A 的资源/工作分离，再按实际需要加入 C 的任务分屏。B 适合偏好传统连接管理器的用户，作为保守方向保留。

可以试什么

  1. 切换 A / B / C，用同一组 12 个打开会话比较侧栏与标签占用。
  2. A 切换“打开会话”和“主机资源库”，观察侧栏从具体会话变成仅分组。
  3. B 点击“全部 12”或按 Ctrl K，搜索并切换隐藏连接；原有连接不关闭。
  4. C 切换三个任务，点击窗格“聚焦”，再返回分屏。
  5. 切换明暗主题、舒适/紧凑密度，收起或展开侧栏。
  6. 使用页面顶部状态选择器，查看连接中、错误、空、部分失败与只读状态；可以取消、重试或确认启用控制。
  7. 终端可以输入 hostname、whoami 和 pwd；其他命令只显示原型提示。

原型范围：导航、布局、可见标签限制、分屏聚焦与连接状态。没有真实 SSH/RDP/VNC、文件传输、持久化工作区或操作系统级快捷键抓取。不同方案里的数据仅存在于当前页面内存中，刷新会恢复初始样本。
