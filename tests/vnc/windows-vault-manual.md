# Windows 凭据设置人工验收（#214）

本步骤只操作维护者预先准备的独立测试目录和复制的 Adit 二进制，不能在
用户日常配置里测试。目录应仅含 `SYNTHETIC vault manual 15918` 这一条
VNC 配置；启用 `keyring_migrated`，关闭自动更新、连接日志、同步和剪贴板。
复制二进制可避免测试窗口锁住开发目录中的构建产物。保留配置目录供冷启动，
不能使用每次启动都会重建 profiles 的 native DPI harness 代替普通入口。

目标由 `start-vault-manual.sh` 在独立容器中启动，Docker 仅发布
`127.0.0.1:15918:15918`，真实 TigerVNC、VncAuth、800×600 蓝色桌面。
唯一公开合成 VNC 密码为 `adit-ci`。本记录中的测试主密码 A
`SyntheticVault-A-2026`、B `SyntheticVault-B-2026` 也是公开测试值，
不得用于任何实际账户或真实凭据。

维护者提供测试目录内的 `start-manual.ps1`。由人工在 PowerShell 中执行
该文件，脚本只给新进程设置 `ADIT_CONFIG_DIR`，启动复制的测试应用，
随后恢复父进程环境。确认窗口里没有日常会话，才继续以下步骤。
安全/认证表单由人工操作；自动化只核对这个独立目录中的版本、条目数、
备份、散列及测试服务端连接事件，不读取或回显输入的密码。

1. 双击唯一的合成 VNC 配置，输入 `adit-ci` 并保存密码，确认真实蓝色桌面。
2. “文件 → 设置 → 应用 → 凭据库主密码”先点“读取状态”，确认兼容模式。
   用 A 启用主密码，确认成功及 v2 状态；维护者核对原模式备份和加密文件。
3. 锁定凭据库，确认既有会话继续运行。关闭该 VNC 标签再从普通侧栏重连，
   应拒绝读取锁库中的保存密码；看到锁库提示/手动输入入口后取消。
4. 设置里用错误主密码解锁，确认可见错误；再用 A 解锁。维护者核对错误
   解锁没有改变凭据文件。正常连接应可以使用已保存的 VNC 密码。
5. 完全退出这个测试 Adit，再运行同一个启动文件。确认进程确已更换、
   启动后仍锁定；设置中读取状态并用 A 解锁，再从普通侧栏双击连接，
   不应再次要求 VNC 密码。冷启动后仅蓝色画面不能替代新服务端认证记录。
6. 导出到**同一测试目录**的 `vault-export-A.json`，确认成功；不覆盖其他
   文件。维护者核对导出字节与当时加密库一致。
7. 用 A 将主密码改成 B；锁定后 A 应被拒绝，B 应能解锁。
8. 用 B 关闭主密码保护，确认兼容模式；保存的 VNC 凭据仍可连接。
   维护者核对当前为 v1 密文、原 v2 备份存在，不能把 v1 当成明文。
9. 导入刚才 A 保护的导出文件：先用错误密码验证拒绝且当前文件不变；
   再用 A 完成导入。确认替换前备份保留、导入后锁定，用 A 解锁后可连接。
10. 重新打开导出文件选择器并取消，确认当前凭据库和原导出文件均不改变。

每项记录通过/失败/未验收及可见提示；遇到失败保留原文件，不手工修复后
再冒称该轮通过。不要把密码、credential 文件、可解密备份或真实桌面截图
提交到仓库。最终结果只归档合成环境的操作方式、二进制散列、版本、条目数、
文件散列和服务端认证元数据。验收完成后关闭复制的测试应用并清理这一个
容器及测试目录；不能删除日常配置或停用其他 VNC 服务。
